0 · Final model · D2, one-way cross-attention (WavLM layer 6)

Best of all detectors over the 10 test sets. LFCC tokens query frozen WavLM tokens from layer 6; the WavLM tokens are never modified, so the classifier always keeps a clean WavLM view.

Layer 6, not the last layerA per-layer probe (notebook 04) is best in the middle of WavLM and weak at both ends; averaged over all test sets layer 6 is best (13.0% EER vs 17.2% for layer 12).
One-way attentionOnly LFCC is updated. D3 (two-way) fits 2019 audio slightly better but generalises worse; likely because LFCC's 2019 recording and codec cues stay out of the WavLM view in D2 (not yet tested directly).
Results (EER, lower is better)Mean over 10 test sets 11.0% (A2 12.5%, D3 11.5%) · 2021 LA eval 10.1% (A2 14.3%) · 2021 DF eval 10.0% (A2 10.7%) · In-the-Wild 19.9% (A2 19.2%).
TrainingTrimmed ASVspoof 2019 LA train, early stopping on dev loss, single run. WavLM stays frozen; only projections, two attention blocks and the classifier are trained.

1 · Add a dataset (inside SystemCode/)

Place datasets under /data/raw/. Models consume manifest CSVs, not dataset directories directly. Follow data/README.md for official download links and expected layouts.

  1. Download / place the corpus in data/raw/<dataset>/. Verify license, protocol files and labels.
  2. Configure paths and protocol metadata in configs/data.yaml (or the active dataset configuration).
  3. Build a dataset-specific manifest builder in src/audio_df/data/manifests.py; emit utt_id, path, label and available speaker/attack metadata. Keep train/dev/test partitions disjoint.
  4. Expose and validate the builder through scripts/prepare_data.py and scripts/check_data.py. Register the resulting manifest with the runtime before using it as a test set. 
uv run data-prepare --help
uv run data-check --verify --paths
uv run data-degrade --conditions all --workers 4
SpoofCeleb (training) and PhonemeDF (evaluation): phase 1 done, not yet merged into this repo. Until then Run trains on ASVspoof 2019 LA only.

2 · Where code belongs

modules/ · Model logicLFCC, GMM, frozen WavLM, neural heads, fusion attention and detector save/load/score behavior. Add new trainable heads here.
pipelines/ · Experiment wiringSmall architecture entry points (A1, A2, A4, D1–D3). Compose modules and delegate train/evaluate/run to the shared runtime.
helpers/ · Reusable utilitiesAudio, signal trimming, feature caches, device selection, training, metrics, artifacts.py (which systems this machine has, their thresholds) and notebook helpers (research/).
data/ · Dataset logicManifest builders, synthetic data and controlled signal degradation; command-line data operations live in scripts/.
pipeline→modules→runtime.py→evaluation.py + helpers/metrics.py

runtime.py manages commands, artifact selection, dataset manifests and evaluation runs. evaluation.py scores results through one metrics implementation. Trained weights live in artifacts/<architecture>/<timestamp>/, each system's threshold in artifacts/<architecture>/threshold.json; evaluation results live in runs/.

Dataset roles: train learns parameters; dev is validation and threshold calibration, not a final benchmark; eval and external/controlled test sets report final performance. 2019 LA train, dev and eval are silence-trimmed (raw training learned the silence shortcut, notebook 02). External datasets are evaluated raw.

Quick run: uv run <architecture> {run|train|evaluate} [flags] — e.g. uv run d2 evaluate --i 2019LA --testsets dev,eval. run trains + evaluates; train saves an artifact; evaluate loads an artifact and scores. Use --help for flags (--i, --o, --root, --seed, --testsets, --model-from).

Phase 2 · Decision layer: arbitration

Tried first: one detector + JEV/LAYAJEV or LAYA reads one frozen detector's score (A3, FP1, FP2). FP1: JEV repeated D2 on all 180 clips, 0 errors corrected. Dropped.
Now: arbitration (adversarial ensemble)Several frozen detectors score the clip. When they disagree, a judge (LAYA or JEV) decides which to trust, or abstains.
Codemodules/arbitrator.py (request + judge), configs/arbitrator.yaml (judge, request variant), uv run arbitration (fixed In-the-Wild test), notebook 06 section 2 (prompt playground).
StatusGiven probabilities, LAYA follows the detector listed first; given verdicts only, it answers spoof every time. It never abstains (notebook 06). Prompt work in progress; JEV next.
frozen detectors (A1 … D3)→verdict · P(bona fide) · error rate→judge: LAYA / JEV→bona fide / spoof / uncertain

Never send labels, clip IDs or dataset names. Threshold and P(bona fide) come from each artifact's threshold.json.

4 · Connect the application

frontend/→FastAPI · backend/app.py→trained artifact→score / verdict

Endpoints: /api/health, /api/model, /api/models (detectors on this machine, judges), /api/detect (clip + detector), /api/compare (two detectors + judge), /api/rankings. Pages: single detector, compare & arbitrate (shows the request sent to the judge), rankings. 

# start with A2; any system on this machine can be picked in the UI
ADF_SYSTEM=a2 uv run uvicorn backend.app:app --reload

# weights in another folder (e.g. a mounted volume)
ADF_ARTIFACTS=/models ADF_SYSTEM=d2 uv run uvicorn backend.app:app

Only systems with a COMPLETE artifact on the machine are offered. Threshold: ADF_THRESHOLD if set (start-up system only), else artifacts/<system>/threshold.json (written after every evaluation). JEV is offered only when TYPESAFE_API_KEY is set.

The rankings page reads artifacts/rankings.json, built from runs/ by uv run make-rankings; copy it into the deployed volume after new evaluations. It is not tracked in git.
