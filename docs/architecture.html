1 · Add a dataset (Everything is done inside SystemCode/) [Chandu]

Place datasets under /data/raw/. Models consume manifest CSVs, not dataset directories directly. Follow data/README.md for official download links and expected layouts. (TL;DR: Download the dataset, then ask Claude or ChatGPT to read data/README.md and update configs/data.yaml, src/audio_df/data/manifests.py, scripts/prepare_data.py, and scripts/check_data.py so the commands below support the new dataset.)

  1. Download / place the corpus in data/raw/<dataset>/. Examples for future integration: SpoofCeleb and PhonemeDF. Verify license, protocol files and labels.
  2. Configure paths and protocol metadata in configs/data.yaml (or the active dataset configuration).
  3. Build a dataset-specific manifest builder in src/audio_df/data/manifests.py; emit utt_id, path, label and available speaker/attack metadata. Keep train/dev/test partitions disjoint.
  4. Expose and validate the builder through scripts/prepare_data.py and scripts/check_data.py. Register the resulting manifest with the runtime before using it as a test set. 
uv run data-prepare --help
uv run data-check --verify --paths
uv run data-degrade --conditions all --workers 4
Current Run accepts ASVspoof 2019 LA as its training dataset. Adding SpoofCeleb training or PhonemeDF evaluation requires explicit runtime/manifest integration; downloading alone does not enable them.

2 · Where code belongs

modules/ · Model logicLFCC, GMM, frozen WavLM, neural heads, fusion attention and detector save/load/score behavior. Add new trainable heads here.
pipelines/ · Experiment wiringSmall architecture entry points (A1, A2, A4, D1–D3). Compose modules and delegate train/evaluate/run to the shared runtime.
helpers/ · Reusable utilitiesAudio, signal trimming, pooled/temporal feature caches, device selection, training, metrics and notebook research functions.
data/ · Dataset logicManifest builders, synthetic data and controlled signal degradation; command-line data operations live in scripts/.
pipeline→modules→runtime.py→evaluation.py + helpers/metrics.py

runtime.py manages commands, artifact selection, dataset manifests and evaluation runs. evaluation.py scores results through one metrics implementation. Training artifacts live in artifacts/<architecture>/; evaluation results live in runs/.

Quick run: uv run <architecture> {run|train|evaluate} [flags] — e.g. uv run d2 evaluate --i 2019LA --testsets dev,eval. run trains + evaluates; train saves an artifact; evaluate loads an artifact and scores. Use --help for flags (--i, --o, --root, --seed, --testsets, --model-from).

3 · Detectors and decision policies [Chakit - JEV and LAYA]

Code Architecture Implementation
A1 LFCC → GMM pipelines/a1.py
A2 Frozen WavLM Base+ → neural head pipelines/a2.py
A4 LFCC → neural head pipelines/a4.py
D1 Pooled LFCC + WavLM → concatenation pipelines/d1.py
D2 Temporal LFCC → WavLM cross-attention pipelines/d2.py
D3 Bidirectional LFCC ↔ WavLM cross-attention pipelines/d3.py

To add an architecture: implement the detector/head in modules/, expose training/scoring/save/load behavior, add a small pipelines/<name>.py using Run, and register its CLI in pyproject.toml. Reuse existing caches rather than extracting WavLM again. 

uv run d2 train --i 2019LA
uv run d2 evaluate --i 2019LA --testsets dev,eval
uv run pytest -q

P2 · LAYAAlternative policy on the same evidence packet and frozen detector. Compare it fairly against P1 and the unassisted detector.

Implement policy logic in modules/ and orchestration in pipelines/. Do not retrain the detector for policy comparisons. Do not pass ground-truth labels or dataset IDs into evidence. Compare A2 vs A3 and the same fusion model with/without P1/P2. Define the evidence schema and API before integration.

4 · Connect the application

frontend/→FastAPI · backend/app.py→trained artifact→score / verdict

The backend loads a completed artifact once, via the architecture's .load(). It serves /api/health, /api/model, and /api/detect; the static frontend is served from frontend/. 

# Use the latest completed A1 artifact
ADF_SYSTEM=a1 uv run uvicorn backend.app:app --reload

# Pin a specific model and its dev-selected threshold
ADF_SYSTEM=a2 ADF_MODEL_FROM=artifacts/a2/<id> \
  ADF_THRESHOLD=<threshold> uv run uvicorn backend.app:app

Swap models without changing API code: ADF_SYSTEM selects A1/A2/A4/D1/D2/D3; ADF_MODEL_FROM selects a specific completed artifact. ADF_THRESHOLD must match that artifact's development calibration. Without a threshold, the API returns a score without a verdict. P1/P2 integration is future work.
