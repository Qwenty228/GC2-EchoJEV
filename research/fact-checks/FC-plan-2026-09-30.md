### 2. ASVspoof 5 minDCF (source: arXiv:2601.03944v1 Eq. 1, fetched directly)
- The paper's own formula is `DCF(τ) = β·P_miss(τ) + P_fa(τ)`, `β = C_miss(1−π_spf)/(C_fa·π_spf)`. This is algebraically `raw_DCF(τ)/(C_fa·π_spf)`, i.e. **the paper normalizes unconditionally by `C_fa·π_spf`**, not by "whichever of `C_miss(1−π)` or `C_fa·π` is smaller."
- With the official parameters (Cmiss=1, Cfa=10, π_spf=0.05): `C_miss(1−π)=0.95`, `C_fa·π=0.5`. Since `0.5 < 0.95`, `min(0.95, 0.5) = 0.5 = C_fa·π_spf` — **the two normalizers coincide numerically for these specific parameter values only**, because β≈1.90 ≥ 1 makes the false-alarm term the smaller one.
- **Verdict: behaviour confirmed** (the implementer's planned code will produce numerically correct minDCF under the official parameters) **but reasoning contradicted** (the source does not define a general `min(...)`-based normalization; it fixes the denominator to `C_fa·π_spf` regardless of which term is smaller). Per the project's contradicted-reasoning/confirmed-behaviour rule, this is recorded as both.
- "Miss" = bona fide utterance wrongly rejected; "false alarm" = spoof utterance wrongly accepted — CONFIRMED, matches the user's implicit assumption and matches ASVspoof2019's CM error polarity (no sign-flip risk).
- **Required action:** either implement `DCF = β·P_miss + P_fa` directly (recommended, matches the paper exactly with no conditional logic), or keep the general `min(...)` form but add a code comment stating it is equivalent to the paper's fixed normalizer only because β≥1 for the official parameters, and will silently diverge if C_miss/C_fa/π_spf are ever changed such that β<1.

### 4. SSL models (source: each model's own `config.json`/`preprocessor_config.json`, fetched directly)
- `microsoft/wavlm-base-plus`: 12 transformer layers, hidden=768, `do_normalize=false`. `facebook/wav2vec2-xls-r-300m`: 24 transformer layers, hidden=1024, `do_normalize=true`. Both share an identical 7-layer conv feature encoder (kernel `[10,3,3,3,3,2,2]`, stride `[5,2,2,2,2,2,2]`, total stride 320 → 50 Hz frame rate).
- `output_hidden_states=True` → **13** tensors (WavLM Base+: embedding + 12 layers) and **25** tensors (XLS-R 300M: embedding + 24 layers) — CONFIRMED by direct arithmetic on each model's own `num_hidden_layers`.
- For a 64,000-sample (4 s @ 16 kHz) input: **199 frames**, both models (derived from the standard no-padding Conv1d length formula applied to each model's own published kernel/stride arrays; not independently re-traced against the actual `modeling_*.py` source, flagged medium confidence on the *implementation* matching the config-only derivation, though this is standard, well-documented behaviour for this model family).
- Licenses: XLS-R 300M has an explicit `apache-2.0` HF tag — CONFIRMED. WavLM Base+ has **no HF `license:` tag at all**; the only license artifact found is the UniSpeech GitHub repo's root LICENSE file (CC-BY-SA-3.0, fetched and read directly) — this is a copyleft-style license, materially different from XLS-R's Apache-2.0. **Required action:** flag this asymmetry to whoever writes the final report's licensing/compliance section; do not assume WavLM checkpoints are as freely reusable as XLS-R's.
